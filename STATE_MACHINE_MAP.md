# Current state machines: owners, contracts and transition tests

Reviewed 2026-11-08, with the independent-review corrections applied against `ffa65879` plus the existing working tree. The original survey began at `65a55921`; quarter, Schoology and catalog work was subsequently committed separately. This batch preserves that work. Deck slices and save/resume are committed in `4e10ae8e`; the earlier audit's WIP labels no longer describe that feature. Implementation checks and independent release approval are separate: this corrected batch still requires the release review and teacher sign-off.

**Decision:** keep the existing modules and make ownership, admission and terminal outcomes explicit at their boundaries. For users this prevents stale screens and falsely successful saves. For developers it gives each operation a concrete contract and reproducible failure case. For agents it provides a navigable owner map and a bounded test command. This change introduces no actor framework, database migration, or grading-policy rewrite.

This is a repository-wide discovery map with deeper behavioral checks of consequential paths. A row groups cooperating machines with the same owner; it is not a claim that every boolean combination, every generated worksheet, external application or deployment was exhaustively explored. Numeric data and time-derived projections are not enumerated as artificial states.

## Start here when changing behavior

1. Locate the owner below. Separate **identity**, **operation instance**, **content version**, and **storage key**; equality of one does not prove the others match.
2. Read the current source and relevant specification. The older [inventory](IMPLICIT_STATE_MACHINES_AUDIT.md) provides finer discovery detail; the [history audit](STATE_MACHINE_HISTORY_AUDIT.md) preserves commit evidence, including deliberate policies. Neither replaces current source.
3. Run the repository's required GitNexus impact check before editing symbols. Inline-script and dynamic-call coverage can be incomplete. An unresolved symbol or empty partial result means unknown impact.
4. Reproduce the transition through the actual implementation with controlled completion order. Check durable state and attribution as well as visible text.
5. Run `npm run test:state-machines`, then relevant integration/release suites. Update the contract and tests together when behavior intentionally changes.

The focused gate is defined in [vitest.state-machines.config.js](vitest.state-machines.config.js). It exercises identity/write races, grade and flashcard ownership, progress-window lifetimes, renderer replacement and video integrity. It is not a replacement for the full root, roster-server, park or Python suites.

Release packaging must include [IMPLICIT_STATE_MACHINES_AUDIT.md](IMPLICIT_STATE_MACHINES_AUDIT.md) and [STATE_MACHINE_HISTORY_AUDIT.md](STATE_MACHINE_HISTORY_AUDIT.md) with this map. Both are present but untracked during review; omitting them from the release would break the published navigation. They retain historical evidence until a separate consolidation preserves it.

## Verification and scope

The independent review reproduced the wrong-account Retry path despite the previous 330-test focused gate passing. It also refuted the delayed-UUID hypothesis for the Desk's normal sign-in sequence. Passing a gate is not proof that all transitions are safe.

The second independent review found two additional evidence gaps: removing pending-storage refusal guidance (D35) or the card-log repetition guard (D23) survives the current tests. The source includes those protections, but this map does not claim adequate regression coverage for them.

- [desk-flashcard-owner-recovery.test.js](tests/desk-flashcard-owner-recovery.test.js): **21 behavioral cases passed** with real roster sign-in, deck scoring, finish UI, mark writes, gradebook client and queue code. Network responses, timers and unrelated presentation are controlled. Against the first pre-fix snapshot, three cases failed and three controls passed. The Desk-switch test kills the original M11 mutation that removed the finish-time guard. Current admission also checks the expected identity inside commit, so a redundant outer guard is not the sole defense.
- Second fix pass: the already-best replay test rejects an account switch during the first grade read. Removing only the post-refresh owner check (D36), in an isolated test copy, makes it fail on the forbidden ledger POST; production source was never mutated. Two username-case/whitespace tests failed before normalization and now pass. Alias comparison trims and ignores case while keeping the UUID check and existing storage keys.
