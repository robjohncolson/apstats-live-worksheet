# Phase 98A — Real Font Table Hunt via cpu.read8 trace

## Context

TI-84 Plus CE ROM transpiler project. The home screen mode row renderer at `0x0a29ec` reads mode text from buffer `0xD020A6..0xD020BF` (26 bytes ASCII) and draws glyphs via the single-char print helper at `0x0a1799`. The font table address is **unknown** — Phase 97C disproved the earlier hypothesis that `0x003d6e` was a font table (it turned out to be OS code, not glyph data).

Your job: write a probe that seeds the mode buffer with a SINGLE known ASCII character, runs the mode row renderer, traps every `cpu.read8` that touches the ROM flash region (`0x000000..0x3FFFFF`) during the render, and identifies the font table base address + glyph stride.

### Setup

```js
import { createExecutor } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';
import { pathToFileURL, fileURLToPath } from 'node:url';
import path from 'node:path';
import fs from 'node:fs';

const __dirname = path.dirname(fileURLToPath(import.meta.url));
const romBytes = fs.readFileSync(path.join(__dirname, 'ROM.rom'));
const mod = await import(pathToFileURL(path.join(__dirname, 'ROM.transpiled.js')).href);
const BLOCKS = mod.PRELIFTED_BLOCKS;

const mem = new Uint8Array(0x1000000);  // 16MB — critical, NOT 4MB
mem.set(romBytes);
const peripherals = createPeripheralBus({ pllDelay: 2, timerInterrupt: false });
const executor = createExecutor(BLOCKS, mem, { peripherals });
const cpu = executor.cpu;
```

### Boot sequence

1. Cold boot: `executor.runFrom(0x000000, 'z80', { maxSteps: 20000, maxLoopIterations: 32 })`
2. Reset stack/IFF: `cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0; cpu.sp = 0xD1A87E - 3; mem.fill(0xFF, cpu.sp, 3);`
3. Run OS init: `executor.runFrom(0x08C331, 'adl', { maxSteps: 100000, maxLoopIterations: 10000 })` — terminates at step 691 (known)
4. Post-init: `cpu.mbase = 0xD0; cpu._iy = 0xD00080; cpu._hl = 0; cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0; cpu.sp = 0xD1A87E - 3; mem.fill(0xFF, cpu.sp, 3); executor.runFrom(0x0802b2, 'adl', { maxSteps: 100, maxLoopIterations: 32 });`
5. Snapshot RAM+CPU for reset between experiments

### Mode buffer setup

Seed `0xD020A6..0xD020BF` (26 bytes) with a pattern that has ONE distinct char surrounded by spaces:

- **Experiment 1**: all 0x20 (spaces), except `mem[0xD020A6] = 0x41` ('A')
- **Experiment 2**: all 0x20 (spaces), except `mem[0xD020A6] = 0x42` ('B')
- **Experiment 3**: all 0x20 (spaces), except `mem[0xD020A6] = 0x30` ('0')

Between experiments, reset mem from snapshot and reset cpu fields.

### ROM read trap

Wrap `cpu.read8` to append `{addr, pc, val}` to a log for every read where `addr >= 0x000000 && addr < 0x400000` (ROM region). Capture `cpu._pc` at time of read if available; otherwise tag with block-level PC via `onBlock`. Do NOT capture RAM reads — only ROM.

```js
const origRead8 = cpu.read8.bind(cpu);
const romReads = []; // [{step, addr, val}]
let inRender = false;
let stepCounter = 0;
cpu.read8 = (addr) => {
  const value = origRead8(addr);
  if (inRender && addr >= 0 && addr < 0x400000) {
    romReads.push({ step: stepCounter, addr, val: value });
  }
  return value;
};
```

### Run mode row renderer with trap active

```js
inRender = true;
const result = executor.runFrom(0x0a29ec, 'adl', {
  maxSteps: 50000,
  maxLoopIterations: 500,
  onBlock: () => { stepCounter++; },
});
inRender = false;
```

### Analysis

The font table must be indexed by char code. For char 'A' (0x41), the OS probably computes `fontBase + (0x41 - baseChar) * stride`. Look for:

1. **Clustered ROM reads** — sequential reads from a small range (the glyph itself, typically 8-28 bytes). A 14×14 or 11×14 TI font is common.
2. **Different base reads across experiments** — 'A' vs 'B' should read bytes exactly `stride` apart. 'A' vs '0' should read bytes `(0x41-0x30)*stride = 0x11*stride` apart.
3. **Exclude known reads** — ignore ROM reads from 0x0a1799-0x0a1900 (the print helper code itself), 0x0a29ec-0x0a2b72 (renderer code). Only look at DATA reads.

Compute:
- Unique ROM addresses read during each experiment, de-duped
- Diff between experiments: `readsForA - readsForB` should point at the font base
- Candidate font base = the smallest address in the post-diff set
- Candidate stride = (fontReadsFor_B_base - fontReadsFor_A_base) or (readsFor_0_base - readsFor_A_base) / 0x11

## Calling convention notes

- The `cpu.read8` wrap is called from Z80 instruction helpers — it fires on every LD from memory, but NOT on instruction fetch (the executor uses direct block lookup). Good — no opcode noise.
- ROM is read-only in this transpiler (Phase 27 write-protect). A font table would be in flash 0x000000-0x3FFFFF.
- Glyphs in TI-84 CE are typically 11×14 pixels stored as 14×2 bytes (28 bytes/glyph) OR 14×1 bytes (14 bytes/glyph, 1bpp). Either is possible.
- Char code may not be raw ASCII — TI uses remapped char codes. 'A' might be stored as index 0x0A or similar. The experiments will reveal the actual mapping via the diff.
