TI-84 CE ROM transpiler project. We built a 5-stage home-screen composite ("P91/96 Home Screen ★") that renders mode text + history area + entry line, but the status bar r0-16 is all WHITE because icon color data at 0xD02ACC is 0xFF (uninitialized) at 100k-step boot. ## Boot pattern to use
```js
import { createExecutor } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';
import { pathToFileURL, fileURLToPath } from 'node:url';
import path from 'node:path';
import fs from 'node:fs';

const __dirname = path.dirname(fileURLToPath(import.meta.url));
const romBytes = fs.readFileSync(path.join(__dirname, 'ROM.rom'));
const mod = await import(pathToFileURL(path.join(__dirname, 'ROM.transpiled.js')).href);
const BLOCKS = mod.PRELIFTED_BLOCKS;

const mem = new Uint8Array(0x1000000);
mem.set(romBytes);
const peripherals = createPeripheralBus({ pllDelay: 2, timerInterrupt: false });
const executor = createExecutor(BLOCKS, mem, { peripherals });
const cpu = executor.cpu;

// Cold boot (z80 mode)
executor.runFrom(0x000000, 'z80', { maxSteps: 20000, maxLoopIterations: 32 });
cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0;
cpu.sp = 0xD1A87E - 3; mem.fill(0xFF, cpu.sp, 3);

// OS init — USE 500_000 STEPS (not the usual 100_000)
executor.runFrom(0x08C331, 'adl', { maxSteps: 500000, maxLoopIterations: 10000 });
cpu.mbase = 0xD0; cpu._iy = 0xD00080; cpu._hl = 0;
cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0;
cpu.sp = 0xD1A87E - 3; mem.fill(0xFF, cpu.sp, 3);
executor.runFrom(0x0802b2, 'adl', { maxSteps: 100, maxLoopIterations: 32 });
```

CPU_FIELDS to snapshot: `['a','f','_bc','_de','_hl','_a2','_f2','_bc2','_de2','_hl2','sp','_ix','_iy','i','im','iff1','iff2','madl','mbase','halted','cycles']`

## Task: create `TI-84_Plus_CE/probe-phase97a-500k-boot.mjs`

**Step 1**: Boot as above with 500k OS init steps. Handle the case where 500k steps takes a long time — log progress every 100k steps if possible, but don't block on logging.

**Step 2**: Read and log:
- `mem[0xD02ACC]` (status icon fg color byte) — is it still 0xFF, or populated?
- `mem[0xD02ACD]` (next byte) — also possibly color data
- `mem[0xD02AD0..0xD02AD8]` (nearby color-data range — log all 9 bytes)
- `mem[0xD020A6..0xD020BF]` (26-byte mode buffer) — is it populated by 500k boot?
- Mode state hot bytes from Phase 75: `mem[0xD00085]`, `mem[0xD0008A]`, `mem[0xD0008E]`, `mem[0xD00092]`

**Step 3**: Snapshot `ramSnap = new Uint8Array(mem.slice(0x400000, 0xE00000))` and `cpuSnap = Object.fromEntries(CPU_FIELDS.map(f => [f, cpu[f]]))`.

**Step 4**: Run the P91/96 5-stage composite against the 500k snapshot. Use a `clearVram()` that writes 0xAA 0xAA per cell (VRAM_SENTINEL), NOT `mem.set(ramSnap, 0x400000)` alone — the RAM range 0x400000-0xE00000 INCLUDES VRAM at 0xD40000, so mem.set resets VRAM to snapshot state, which may contain stale data. The Phase 91c pattern does both: `mem.set(ramSnap, 0x400000)` then `clearVram()`.

```js
function clearVram() {
  for (let i = 0; i < 320*240*2; i+=2) {
    mem[0xD40000+i] = 0xAA;
    mem[0xD40000+i+1] = 0xAA;
  }
}
function resetCpu() {
  for (const [f, v] of Object.entries(cpuSnap)) cpu[f] = v;
  cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0;
  cpu._iy = 0xD00080; cpu.f = 0x40;
  cpu.sp = 0xD1A87E - 12; mem.fill(0xFF, cpu.sp, 12);
}

// Composite:
mem.set(ramSnap, 0x400000); clearVram(); resetCpu();

// Stage 1: status bar bg
executor.runFrom(0x0a2b72, 'adl', { maxSteps: 30000, maxLoopIterations: 500 });

// Stage 2: seed mode buffer with "Normal Float Radian       "
const modeStr = 'Normal Float Radian       '; // 26 chars
for (let i = 0; i < 26; i++) mem[0xD020A6+i] = modeStr.charCodeAt(i);

resetCpu();
// Stage 3: home row strip
executor.runFrom(0x0a29ec, 'adl', { maxSteps: 50000, maxLoopIterations: 500 });

resetCpu();
// Stage 4: history area
executor.runFrom(0x0a2854, 'adl', { maxSteps: 50000, maxLoopIterations: 500 });

// Stage 5: direct VRAM fill r220-239 white
for (let r = 220; r < 240; r++) {
  for (let c = 0; c < 320; c++) {
    mem[0xD40000+(r*320+c)*2] = 0xFF;
    mem[0xD40000+(r*320+c)*2+1] = 0xFF;
  }
}
```

**Step 5**: After composite, count:
- `drawn` = VRAM cells where 16-bit value != 0xAAAA (sentinel)
- `fg` = cells that are not white (0xFFFF) and not sentinel
- `bg` = cells that are white (0xFFFF)
- Separate counts for row bands: r0-16 (status bar), r17-34 (mode row), r37-74 (history area), r220-239 (entry line)
- rMin / rMax (smallest/largest row with non-sentinel content)

**Step 6**: Print a 40-row ASCII art preview of r0-40 using the same asciiRow helper from Phase 91c:
```js
function asciiRow(row) {
  let s = `r${String(row).padStart(3,'0')}: `;
  for (let c = 0; c < 320; c++) {
    const px = mem[0xD40000 + (row*320+c)*2] | (mem[0xD40000 + (row*320+c)*2+1] << 8);
    s += px === 0xAAAA ? '.' : px === 0xFFFF ? ' ' : px === 0x0000 ? '#' : '+';
  }
  return s;
}
```
