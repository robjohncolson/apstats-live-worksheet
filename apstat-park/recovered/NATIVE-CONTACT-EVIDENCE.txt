FUN_7ff72bc1e4a0: ordinary rectangle/mixed-shape pair response
  Actor displacement is current(+4c) minus last accepted position(+64).
  Current world bounds come from bb70550. Each axis checks which side was
  previously separated. Rollback fractions are clamped to [-1,0].
  Opposing movement rewinds both trajectories by the same fraction.
  Same-direction movement rewinds only the faster trajectory.
  If both fractions are nonzero, reject an axis whose perpendicular
  intervals do not meet at the rollback time (strict < rejection).
  Candidate positions are current + displacement * rollback, float32.
  Cancellation to a negligible correction restores the previous axis.
  Apply +/-.01 to the selected moving body, clamped against its previous
  position. A resting exact-edge body is not lifted away from its support.
  No mass or equal-share overlap division occurs in this branch.
  No valid axis: ordinary bodies restore their accepted positions.
  Flags 2 set and 8 clear divert to recursive bc20280; NOT implemented here.

FUN_7ff72bc13830: contact insertion
  Contact records are unique by other-body ID, not by normal. The response
  inserts X before Y, so simultaneous corner contact retains X.
  Reciprocal-UP suppression and contact state transitions still belong to
  the unported global registry; the pair helper does not simulate them.

FUN_7ff72bc1e050: pair eligibility and iteration
  Pair must overlap at current positions and must NOT overlap at accepted
  positions (bc119c0 vs bc11be0). Tangency is not overlap.
  The new helper preserves these rectangle overlap gates. It does not
  own category masks, active/moved flags, registration order, the two solver
  phases, rollback of the global list, or recursive fixed-body propagation.

FUN_7ff72bc1da80: global pass, not yet ported
  Snapshot body positions; restore old scales while queuing scale changes.
  Apply map displacement to eligible bodies. Repeat pair phases 0 and 1.
  Call world hook, resolve queued scale changes, finalize every body.
  Finally scan registered pairs for overlap callbacks. A accepted callback
  runs before B, without another enabled check between those two callbacks.
  bc146c0 commits accepted positions, transform callbacks and actor/map
  contact lifecycles; it is NOT the pair response function.

Standalone registered-body solver checkpoint (native-body-world.mjs):
  bc1e050 phase 0 handles ordinary pairs; phase 1 handles one priority body.
  Phase 1 snapshots every registered body's position. A failed recursive
  move restores that entire snapshot, preserves the temporary demotion bit,
  and retries phase 0. Previously inserted contact rows survive rollback.
  bc20280 rejects bit 0x10, requests map movement, compares actual movement
  with requested movement using bb93520 (componentwise FLT_EPSILON), then
  invokes bc203a0 unless both components are at most 2^-52.
  bc203a0 expands each non-negligible displacement component by signed .001,
  traverses registered bodies in order, filters active/type/category/new
  overlap, moves each reached body and recursively propagates the expanded
  displacement. It does not invent contact rows for these recursive moves.
  Raw bc2056e..bc20579 confirms the expanded vector is passed in R8; Ghidra
  drops this third recursive argument in its C rendering.
  bc21410 uses signed .01 when transferring a priority body's rejected
  candidate correction into the other body's requested displacement.
  bc21070 is !(flags & 0x10), not the priority predicate bc210a0.
  bc12490 type-bit-1-clear branch directly updates position but leaves its
  output displacement untouched; the caller initialized it to zero. This
  means a nonzero such move can mutate position and return failure. Preserve
  that behavior for the outer rollback; do not force success.
  Raw constants also checked: bcb9a20 = .0010000000474974513;
  bcc7ec8 = 2.220446049250313e-16 (2^-52 represented as float).
  Contact insertion includes unique IDs, reciprocal-UP suppression and
  fixed-capacity exclusion. Geometry uses rectangle/mixed bounds only.

Standalone callback checkpoint (native-body-contacts.mjs):
  bc13c60 offsets the querying body by contact.normal * .5 and uses strict
  current overlap. New state 0 becomes 1, dispatches BEGIN, then STAY.
  Existing accepted contact dispatches STAY. Lost accepted contact dispatches
  END; a lost new contact or missing registry entry is simply discarded.
  BEGIN can disable a body without cancelling that already-accepted STAY.
  Player flag 4 requires a separate half-width upward-probe handler first.
  bc1da80 overlap scan requires enabled bodies and ordered matrix eligibility,
  but does not require physical type or moved bits. A callback runs before B.
  B's callback is fetched after A's callback, without rechecking enabled bits.
  The next pair does recheck enabled state through bc119c0.

Native map checkpoint (supersedes the missing map-sweep/lifecycle items above):
  native-map-collision.mjs implements bc2fca0, bc304f0, bc12490 and bc14040.
  bc2fca0 first probes the requested cardinal directions. A blocked component
  is zeroed while the other can continue. It then visits crossed tile rows
  and columns in boundary-time order; equal times choose Y. A blocked edge
  commits trajectory motion to first contact plus a signed .01 gap. Movement
  and actor-position addition are independently float32, not one double sum.
  bc12490 subtracts actual motion, projects out the blocked normal and repeats
  until no contact remains. New map normals deduplicate against both retained
  and pending lists; pending capacity is eight. Non-map bodies move directly
  without writing output motion, matching the previously recovered contract.
  bc304f0 normalizes the supplied direction, scales it to .5, collapses the
  shifted rectangle onto its leading edge, divides by chip size and truncates
  toward zero. Both scan endpoints are inclusive. bc28270/bc28390/bc284a0
  clamp map coordinates to the edge cell, including beyond map boundaries.
  Raw bcc8a30 int32[26] verified: IDs 0/1 have flags 0; IDs 2..25 flags 1.
  Higher IDs use the explicit stage custom table. Missing custom IDs pass.
  Raw bcbabe8 is FLT_MAX; bcb69c0 is -FLT_EPSILON. Boundary pixel accumulators
  are uint32 (raw bc2fff9 and bc30037 convert zero-extended values via RAX).
  Numeric IDs match recovered stage/stage_common.lua. The conversion helper
  rejects unknown names or custom IDs without an explicit custom flag table.
  bc14040 processes retained contacts before pending ones. Retained contacts
  emit STAY or END; accepted pending contacts emit BEGIN then STAY and join
  the retained list. The pending branch has no body-enabled check; this is
  preserved and tested. Pending entries are cleared after the pass.

Standalone circle/support checkpoint:
  native-body-overlap.mjs now shares bc119c0/current and bc11be0/accepted
  overlap behavior across the reconstructed world and contact lifecycle.
  Both-circle queries use Euclidean distance; mixed pairs use strict AABB.
  Raw bc11a38..bc11a68 confirms circle center = actor position * axis scale.
  Raw bc11c5b..bc11cbe confirms accepted-position radii are multiplied by
  max(scaleX,scaleY), unlike the current query's unscaled descriptor radii.
  These asymmetric native operations are preserved, not normalized away.

  native-circle-pair.mjs implements bc1f1c0. Original displacement directions
  are normalized first. Same-direction radial motion zeros one displacement.
  Relative movement then supplies a quadratic contact-time solution capped
  at 1. Each moving body rewinds displacement*time plus .001 along its
  original direction, capped at its full original displacement. The normal
  is the normalized vector between the resolved positions. Mass and bounce
  response remain actor callbacks. Unlike the rectangle path, this resolver
  does not divert a single priority body to recursive displacement.
  Raw constants bcff5c0=2, bcff650=4, bcb9a20=.001 were checked directly.
  Circle response and overlap are connected to the standalone world solver
  and lifecycle, with tests for opposing/overtaking/stationary/glancing hits,
  full rollback, mixed corners, strict tangency and scaled queries.

  native-body-support.mjs implements bc1d580 directional neighbor queries:
  candidate must be enabled and physical; query must be physical but its
  enabled bit is ignored. Matrix order is candidate->query. Current overlap
  excludes the candidate; a .5 direction-offset query must newly overlap.
  Native center-vs-edge comparisons and a 16-neighbor cap retain registry
  order. Horizontal comparisons are intentionally kept as written in native:
  selector bc1d6a3..bc1d6c0 and compare bc1d761..bc1d76a confirm direction 2

Standalone scale and world-pass checkpoint:
  native-body-scale.mjs implements bc12760 rectangle displacement probes and
  bc1f7b0 deferred scale resolution. The displacement probe moves one body,
  rewinds crossed axes against the other rectangle, applies positional .01
  separation, and returns resolved position minus the starting position. It
  does not use the pair solver's perpendicular-axis rejection or old-overlap
  exclusion. This distinction also changes float32 rounding of allowed motion.

  A strict shrink on BOTH scale axes applies directly. Otherwise changes
  within .001 on both axes are ignored, and non-rectangle growth is ignored.
  Rectangle growth computes four corner movements from old to desired bounds,
  restores accepted scale, probes those movements without sliding against the
  map, then against eligible rectangles. Each probe restores actor position.
  The smallest clamped allowed/requested component ratio limits the scale.
  A blocked result backs scale toward accepted scale by .02, not the .01 used
  for positions (raw DAT_7ff72bcbbb28 = .019999999552965164).
  An active physical non-rectangle encountered in registry order exits the
  whole growth routine before category/distance checks. This unusual behavior
  is retained and tested. Nonphysical rectangles take desired scale directly.
  Raw bc1fb69..bc1fb7d confirms map input/output alias and slide=false;
  bc1fcdb..bc1fced confirms Ghidra's omitted rectangle-probe delta/output args.

  native-body-pass.mjs implements bc1da80 orchestration and bc146c0 finalization.
  It snapshots entry positions, temporarily restores accepted scales, queues
  up to 32 changed bodies, resolves map movement from accepted positions,
  runs the pair phases, invokes the world after-pairs hook, resolves queued
  scales, finalizes bodies, then dispatches the ordered overlap scan.
  Finalization commits accepted position and clears moved bit first. It emits
  a scale callback only when actual differs from requested, then stores actual
  scale as requested and accepted. Position callbacks receive the correction
  from the entry snapshot, gated by squared distance > FLT_EPSILON. Actor
  contacts are refreshed before map contacts. Callback-caused position edits
  do not retroactively rewrite the already committed accepted position.

  Tests cover all rectangle probe faces, unblocked/blocked growth, shrink and
  tiny-change branches, non-rectangle early exit, .02 scale correction, the
  32-body queue limit, transform/contact/overlap callback order, and a complete
  map-correction-to-contact pass. The reconstructed world pass runs standalone;
  native actor registration and the actor PRE/POST bridge are still needed
  before replacing the existing campaign update loop.
Native registry checkpoint (bc1d110, bc1ffa0, bc200c0):
- native-body-registry.mjs separates ordered bodies from unsigned-ID lookup.
  The circular native list is represented as a stable descending signed-priority
  array. Equal-priority reattachment moves a body behind its current peers.
- World construction enables only category 0/0 and reserves 128 dictionary
  entries with growth disabled. bc20e60 refuses existing keys and overflow;
  bc1ffa0 ignores that result after list insertion. Automatic IDs increment the
  uint32 counter without searching for an unused ID. Explicit IDs do not advance
  the counter. These details were checked directly against the recovered C.
- bc13b50 attaches ownership even after duplicate-ID insertion rejection.
  Attempting to detach that invalid list state throws explicitly in JS instead
  of reproducing the native invalid-pointer dereference.
- bc200c0 removes the list entry and dictionary key but does not clear owner;
  bc13bb0 clears owner before invoking bc14290 contact cleanup. Thus detachment
  does not immediately notify reciprocal contacts. The next neighbor refresh
  silently drops the missing dictionary ID, as bc13c60 specifies.
- Direct bc14290 cleanup while attached notifies accepted reciprocal contacts
  only. It clears own actor contacts, active map count (+e8), and map pointer
  (+140). It does NOT clear pending map count (+138). Constructor bc11f30
  independently confirms these field locations.
- Contact finalization now uses dictionary lookup when a registry is supplied;
  older standalone list fixtures retain their list lookup adapter.
- Seven regression cases exercise ordering/sensor dispatch, automatic-ID
  collision, dictionary capacity, ownership sequencing and cleanup behavior.
  This registry is not yet connected to live campaign actor construction.
