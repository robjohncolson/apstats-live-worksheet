## Workstream B — `skill.penalty` metadata decision → STRIP

### Goal

Close open carry-over (d) from the continuation prompt. The `skill.penalty` field in `data/frq-decompositions.json` is currently metadata-only — `.v6-frq-decomp-block.js` hardcodes 0.05 / 0.10 / 0.15 for formula / correct-drill / wrong-drill penalties and never reads `skill.penalty`. The values in the JSON (0.10 boilerplate on 30/31 skills, 0.05 on u7-frq-scope-limit) aren't meaningfully differentiated. Carry-over says: wire it up or strip it.

### Decision (locked by planner): STRIP

Strip the `penalty` field from every skill in `data/frq-decompositions.json`. The global `maxPenalty: 0.50` cap stays — it's the only meaningful cap and it already caps runaway penalties at the computed level. Per-skill caps are non-trivial to attribute correctly when a formula/drill supports multiple skills (double-counting / first-skill-wins ambiguity), and the authored values don't reflect intentional per-skill differentiation. Cleaner to strip now than to ship ambiguous metadata that future sessions have to re-interpret.

### Required changes

1. **`data/frq-decompositions.json`**: remove `"penalty": 0.XX,` from all 31 skills. Leave everything else in each skill intact. Use an editor or sed-equivalent; verify the JSON still parses after the edit (`JSON.parse(fs.readFileSync(...))`).
2. **`data/frq-decompositions.js`**: this is the sync wrapper (`window.FRQ_DECOMPOSITIONS = ...`). If it's generated from the JSON at build time, regenerate it. If it's hand-maintained, edit it to match.
3. **`.v6-frq-decomp-block.js`** and the inline HTML copy: no logic change (the field is already ignored). But add a one-line comment above `computeEffectivePenalty` noting: `// Per-helper penalties (formula 0.05, correct drill 0.10, wrong drill 0.15). Global cap from decomposition.maxPenalty (0.50).` — replaces any old stale comment that might reference skill.penalty.
4. **Tests**: search for tests that assert `skill.penalty` exists or has a specific value. Delete or update them. Run the full test suite to catch test-level failures.

### Tests for Workstream B
