# Phase 99C — Hardware poll response for 0x006138

## Context

Phase 98C discovered the cold-boot path from 0x08c331 (or 0x08c366 or 0x08c33d) terminates at `lastPc=0x006138` after a fixed number of steps regardless of `maxSteps`. The bytes at 0x006138 are:

```
ed 78       in a,(c)       ; read port C
e6 f0       and 0xF0       ; mask upper nibble
20 fa       jr nz,-5       ; loop until upper nibble clear
0d          dec c          ; switch to adjacent port C-1
ed 78       in a,(c)       ; read that port
cb 57       bit 2,a        ; test bit 2
20 fa       jr nz,-5       ; loop until bit 2 clear
c1          pop bc
c9          ret
```

**This is a hardware poll loop.** It waits for an I/O port to clear its upper nibble, then decrements C, reads the adjacent lower port, and waits for bit 2 to clear. `0x006138` is NOT in `PRELIFTED_BLOCKS` so bumping `maxSteps` can't cross it; we need either (a) a real port response that returns clearing values, or (b) seed the block and trust the walker to lift it.

This task is the peripheral-response approach. Phase 99B (separate dispatch) handles the seed approach.
