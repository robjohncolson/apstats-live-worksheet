# Phase 98C — Alternate Boot Entry Experiments

## Context

TI-84 Plus CE ROM transpiler. Phase 97A established that `executor.runFrom(0x08C331, 'adl', { maxSteps: 500000 })` terminates at **step 691** regardless of maxSteps — it hits `missing_block` at `0xffffff` (synthetic RET sentinel). The status icon color byte `mem[0xD02ACC]` stays 0xFF (white), so status icons render white-on-white and are invisible.

Phase 71 established that the real OS boot is **ISR-driven via BCALL dispatch through jump-table slot 21**, not linear. Slot 21 dispatches to `0x08c366` (state-resume entry). There's also `0x08c33d` (partial-init entry with 10+ external callers).

**Hypothesis**: Running from one of these alternate entries, possibly with `timerInterrupt: true` in peripherals to let the hardware timer drive post-HALT continuation, may produce more than 691 steps and populate `0xD02ACC` with real color data.

## Probe Specification

Base the probe on `probe-phase97a-500k-boot.mjs` which already has the boot + composite measurement harness.

### Experiment matrix (6 total combinations)

| # | entry address | timerInterrupt | maxSteps |
|---|---|---|---|
| 1 | `0x08C331` | false | 500000 | ← baseline (already confirmed 691 steps, for regression check)
| 2 | `0x08C331` | **true** | 500000 |
| 3 | `0x08C366` | false | 500000 |
| 4 | `0x08C366` | **true** | 500000 |
| 5 | `0x08C33D` | false | 500000 |
| 6 | `0x08C33D` | **true** | 500000 |

For each experiment:
1. Fresh `mem`, fresh `peripherals` with the specified `timerInterrupt` flag, fresh `executor`
2. Cold boot: `executor.runFrom(0x000000, 'z80', { maxSteps: 20000, maxLoopIterations: 32 })`
3. Reset stack/IFF: `cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0; cpu.sp = 0xD1A87E - 3; mem.fill(0xFF, cpu.sp, 3);`
4. Run the entry: `executor.runFrom(entryAddr, 'adl', { maxSteps: 500000, maxLoopIterations: 10000 })`
5. Record `steps`, `termination`, `lastPc`
6. Sample these bytes: `mem[0xD02ACC]`, `mem[0xD02ACD]`, `mem[0xD02AD0..0xD02AD8]`, `mem[0xD020A6..0xD020BF]`, mode state bytes `mem[0xD00085]`, `mem[0xD0008A]`, `mem[0xD0008E]`, `mem[0xD00092]`

### Composite check (optional, only if primary test shows progress)

If any experiment produces `mem[0xD02ACC] != 0xFF` OR `steps > 691`, then rebuild the home-screen composite from that snapshot:

- Clear VRAM (0xD40000..0xD40000+153600 to 0xAA bytes = VRAM_SENTINEL)
- Run `0x0a2b72`, then seed mode buf "Normal Float Radian       ", then `0x0a29ec`, then `0x0a2854`, then direct fill r220-239 white
- Count `drawn`/`fg`/`bg` and per-row stats for r0-16 (status bar band)
- Compare fg count to 100k baseline (fg=0 in status bar → anything nonzero is a win)

Reference composite counts from Phase 97A: `drawn=25686 fg=11516 bg=14170` (100k baseline) / `drawn=31138 fg=16062 bg=15076` (at 500k with 50k maxSteps on 0x0a2854).

### Reset handling

The peripherals object carries timer state — do NOT reuse a peripherals instance between experiments. Create fresh `createPeripheralBus({ pllDelay: 2, timerInterrupt: flag })` for each.

If the transpiled ROM module has internal state, you may need to re-import it or reset its block cache — check `ROM.transpiled.js` exports. Use `await import(pathToFileURL(...))` once and reuse `PRELIFTED_BLOCKS` (it's just a data table).

Also: always allocate `new Uint8Array(0x1000000)` (16 MB) — the NMI handler writes to 0xffffff and a 4MB buffer will out-of-bounds.

### Output report

For each experiment, log:
- Experiment ID (1-6), entry addr, timerInterrupt flag
- `steps`, `termination`, `lastPc`
- Mode state bytes
- `0xD02ACC..D` bytes
- Mode buffer (26 bytes, hex)
- Conclusion: "null result" / "PROGRESS: steps > 691" / "PROGRESS: 0xD02ACC populated"

Final verdict:
- Any experiment produce > 691 steps? (Y/N)
- Any experiment populate `0xD02ACC`? (Y/N)
- Any experiment populate the mode buffer with non-0xFF bytes? (Y/N)
- Best experiment (by step count and composite fg pixels)
