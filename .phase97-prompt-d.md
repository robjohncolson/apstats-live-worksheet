# Phase 97D — Mode-Var Reader Probing

## Context
TI-84 CE ROM transpiler. The home-screen mode display buffer at `0xD020A6` (26 bytes ASCII) is populated by an unknown OS function — no static `LD HL,0xD020A6` exists in ROM, so the populator uses a computed address.

Phase 92 already ran write8 traces and found writes from:
- `0x001881` — zeros mode buffer (26×0x00) during OS init
- `0x00287D` — resets buffer to 0xFF (same OS init, runs after 0x1881)
- `0x0A17AE` — context-dependent char write helper

None of those is the home-screen mode-text populator. **This task probes 4 untested candidates** (identified in Phase 75 as mode-var readers — they read bytes in the 0xD00080-0xD000FF mode-state region):
- `0x0a2812`
- `0x0a281a`
- `0x0a29a8`
- `0x0a654e`

Worth probing: one might populate 0xD020A6 as a side effect.

### Step 2: For each target (0x0a2812, 0x0a281a, 0x0a29a8, 0x0a654e), run an isolated probe
Reset from snapshots. Wrap `cpu.write8` to trap writes in these ranges (log addr, value, blockPc, step):
- `0xD020A6..0xD020BF` (main mode buffer)
- `0xD020C0..0xD020D0` (possible adjacent buffer)
- `0xD020E0..0xD020F0` (possible adjacent buffer)

Wrap `cpu.read8` to trap reads from `0xD00080..0xD000FF` (mode-state region). Store a Set of unique addresses read.

```js
function probe(targetAddr, argOverrides = {}) {
  // Reset
  mem.set(ramSnap, 0x400000);
  for (const [f, v] of Object.entries(cpuSnap)) cpu[f] = v;
  cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0;
  cpu._iy = 0xD00080; cpu.f = 0x40;
  cpu.sp = 0xD1A87E - 12; mem.fill(0xFF, cpu.sp, 12);
  for (const [k, v] of Object.entries(argOverrides)) cpu[k] = v;

  const writes = [];
  const modeReads = new Set();
  let currentBlockPc = 0;
  let stepCount = 0;

  const origW = cpu.write8.bind(cpu);
  const origR = cpu.read8.bind(cpu);
  cpu.write8 = (addr, val) => {
    if ((addr >= 0xD020A6 && addr <= 0xD020BF) ||
        (addr >= 0xD020C0 && addr <= 0xD020D0) ||
        (addr >= 0xD020E0 && addr <= 0xD020F0)) {
      writes.push({ addr, val, blockPc: currentBlockPc, step: stepCount });
    }
    origW(addr, val);
  };
  cpu.read8 = (addr) => {
    if (addr >= 0xD00080 && addr <= 0xD000FF) modeReads.add(addr);
    return origR(addr);
  };

  const res = executor.runFrom(targetAddr, 'adl', {
    maxSteps: 30000, maxLoopIterations: 500,
    onBlock: (pc) => { currentBlockPc = pc; stepCount++; }
  });

  // Restore
  cpu.write8 = origW;
  cpu.read8 = origR;

  return { res, writes, modeReads: [...modeReads].sort(), finalPc: currentBlockPc, steps: stepCount };
}
```

### Step 4: Find direct CALL callers of each target in ROM
Scan `romBytes` for the 4-byte pattern `CD lo mid hi` (CALL nn24 in ADL mode) targeting each of 0x0a2812/0x0a281a/0x0a29a8/0x0a654e. Also scan for `C3 lo mid hi` (JP nn24).

```js
function findDirectCallers(target) {
  const loByte = target & 0xFF, midByte = (target >> 8) & 0xFF, hiByte = (target >> 16) & 0xFF;
  const callers = [];
  for (let i = 0; i < romBytes.length - 4; i++) {
    if ((romBytes[i] === 0xCD || romBytes[i] === 0xC3) &&
        romBytes[i+1] === loByte && romBytes[i+2] === midByte && romBytes[i+3] === hiByte) {
      callers.push({ at: i, op: romBytes[i] === 0xCD ? 'CALL' : 'JP' });
    }
  }
  return callers;
}
```

For each caller found, do a SECOND-level probe — run `runFrom(caller.at, 'adl', ...)` with the same write8 trace. Does the caller populate the mode buffer before the target runs?
