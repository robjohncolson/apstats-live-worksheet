## Open questions / ambiguities

1. **`refreshAuthPanelVisibility` re-render path**: The "restore full form" branch in `refreshAuthPanelVisibility` dynamically re-creates the form DOM if `#studentUsername` is missing (i.e., after the signed-in strip replaced it). This re-wires event listeners inline. The `ui.password` keydown (Enter → verify) is NOT re-wired in this path — only the sign-in button and create link are. If the user signs out and then wants to use Enter to sign in, they need to click the Sign In button. Low-impact given the sign-in button is visually adjacent. Flagged for the empirical probe.

2. **`u1-frq-tail-comparison supportingFormulas`**: The `.json` canonical source has `["zscore"]` only; the original `.js` had `["zscore", "empirical-rule"]`. Both were overwritten to `["zscore"]` in the sync rewrite. The empirical rule could be useful here (z=1 → ~16% from 68-95-99.7). Left as-is since `supportingFormulas` was out of scope for this pass — flagged in the audit.

3. **`u5-frq-estimator-comparison supportingFormulas`**: Original `.js` had `["xbar-mean", "xbar-sd"]` but the `.json` had `[]`. The updated `.json` now has `[]` (intentionally tool-free per the plan). The `.js` sync wrapper was updated to match `[]`. If the cartridge should support xbar formulas here for CLT part (b), that's a separate decision.
