## Workstream A — Login bar
- **Blocker** — `study_guide_diagnostic.html:2388-2422` rebuilds the auth form after sign-out, but it only rebinds `#studentLoginBtn` and `#studentCreateLink`. The original `ui.password` Enter handler and `ui.username` change handler are attached once in `init()` (`study_guide_diagnostic.html:5015-5041`) and are destroyed when `section.innerHTML = ''` removes the old nodes. After the first sign-out, pressing Enter in the password field no longer signs in, and changing the username dropdown no longer calls `switchStudentProfile()`. Suggested fix: extract the auth-form listener wiring into a helper and call it both from `init()` and from the restore branch after `ui.username` / `ui.password` / `ui.loginBtn` / `ui.createLink` are re-queried.
- **Concern** — `clearAuthSession()` only flips `authSession` (`study_guide_diagnostic.html:2340-2345`). The sign-out button then calls only `clearAuthSession()` plus `refreshAuthPanelVisibility()` (`study_guide_diagnostic.html:2380-2383`), and the restored form reuses the old `syncStatusText` when it recreates `#syncStatus` (`study_guide_diagnostic.html:2413-2415`). Because `refreshSyncStatus()` is not called, the panel can still say the user is “ready for Supabase sync” after sign-out (`study_guide_diagnostic.html:2592-2599`). Suggested fix: refresh sync status whenever auth changes, ideally inside `clearAuthSession()` / `markAuthenticated()` or immediately after each call site.

## Workstream D — rubric surfacing
- **Blocker** — paper mode bypasses the new disclosure gate. Clicking `Mark complete (paper)` writes `data.frqGrade = { score:'paper', ... }` without AI grading or any answer requirement (`study_guide_diagnostic.html:4168-4175`). `renderGrade()` then renders the official rubric and worked solution for any truthy `grade.score` (`study_guide_diagnostic.html:4712-4777`), so a student can toggle paper mode and immediately reveal the answer key. Suggested fix: gate the disclosures on a real graded score (`grade.score !== 'paper'`) or the same condition used for AI-graded responses.

## Cross-cutting
- **Concern** — the runtime helper config changed outside the authorized `whyItMatters` field. `study_guide_diagnostic.html` reads helper buttons from `window.FRQ_DECOMPOSITIONS` in the `.js` wrapper (`study_guide_diagnostic.html:1766-1779`, `study_guide_diagnostic.html:4497-4516`), and this diff changes live `supportingFormulas` entries in that wrapper, for example `u1-frq-tail-comparison` now only exposes `zscore` (`data/frq-decompositions.js:19-28`), `u5-frq-estimator-comparison` exposes no formulas (`data/frq-decompositions.js:197-205`), and `u9-frq-scatterplot` also exposes no formulas (`data/frq-decompositions.js:374-381`). The new tests only inspect the JSON source (`tests/study-guide.test.js:992-1011`), so unintended helper removals can pass CI while still changing the UI. Suggested fix: either revert non-`whyItMatters` wrapper drift or add parity/runtime tests that assert the `.js` wrapper only changed where intended.
