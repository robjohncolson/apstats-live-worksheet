**CONFIRMED findings**

1. **follow-alongs and curriculum_render — an earlier completion releases another operation's queue lock.** `offline-queue.js:203`. Queue answers with sequences 1 and 3, wait for operation 1, then enqueue a delayed sequence 2. Operation 1 used to delete the lock belonging to operation 3; overlapping reads/writes could replace answer 3 with answer 2. This also occurs when the first write fails. Fix: release the lock only when its stored promise is still this operation's promise. Commits: follow-alongs `c31ee96d6f23`; curriculum_render `029ef49eda70`. Proof: the first two cases in `tests/offline-queue-lock-race.test.js` fail before the fix and pass afterward in both repos. The faulty lock existed in pre-sprint follow-alongs and was carried into Curriculum Render by unification.

2. **follow-alongs and curriculum_render — successful replay deletes a newer, unsent answer.** `offline-queue.js:305`. A successful drain reads the old row while a concurrent enqueue is in progress; its later delete removes the newly written answer. Comparing sequences alone did not make the separate storage operations atomic. Fix: run the final read/delete under the same per-key lock as enqueue and supersede. Commits: follow-alongs `c31ee96d6f23`; curriculum_render `029ef49eda70`. Proof: `tests/offline-queue-lock-race.test.js:56` previously leaves an empty queue and now retains answer 2. This race was present in both pre-sprint versions. The tests execute the real queue with an asynchronous storage adapter, exercising the interleaving hidden by the synchronous memory fallback.

3. **follow-alongs — teacher sign-out leaves the Class Log bearer credential behind.** `roster-client.js:36`; `js/desk-class-log.js:61`. Signing out cleared the roster session but retained `apstats_classlog_token`. A pending sign-in response in another tab could also restore that token after logout, and a stale form could submit after teacher access ended. Fix: central session cleanup removes the Class Log token and teacher-role marker; Class Log sign-in checks teacher access before requesting and before storing the reply. Commit: `c31ee96d6f23`. Proof: `tests/desk-class-log-signout.test.js` and `tests/desk-class-log-signin-race.test.js` — five passing cases, including shared-storage tabs and normal successful teacher sign-in; the logout/race cases failed before repair. The ordinary student UI does not mount the fold; the confirmed exposure was the retained credential, not a demonstrated server authorization bypass.
