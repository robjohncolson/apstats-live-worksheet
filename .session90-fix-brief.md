## Fix 1 (BLOCKER 2a) — Night-mode chart text dark-on-dark

**Bug**: `lib/curriculum-charts.js:23-35` has `isDarkMode()` that reads `document.body.classList.contains('dark-theme')`. The study guide uses a DIFFERENT theme mechanism: `:root[data-theme="night"]` set via `document.documentElement.setAttribute('data-theme', safe)` (see `study_guide_diagnostic.html:20-43` for the CSS variables and line ~5001-5004 for the toggle code). Because `dark-theme` class is never set, `isDarkMode()` always returns false, and `getTextColor()` falls back to `#333333` dark gray — invisible on the night-mode dark background.

**Fix**: edit `lib/curriculum-charts.js` `isDarkMode()` function to read the study guide's theme source. Change from:

```js
function isDarkMode() {
  return document.body.classList.contains('dark-theme');
}
```

to:

```js
function isDarkMode() {
  // Study guide uses :root[data-theme="night"]; curriculum_render uses .dark-theme on body.
  // Check both so the lifted file works in either host.
  return document.documentElement.getAttribute('data-theme') === 'night'
      || document.body.classList.contains('dark-theme');
}
```

This keeps the file usable if it ever gets re-lifted back to curriculum_render, while also working in the study guide today.

**Tests**: add a source-string test in `tests/audit-script.test.js` or `tests/study-guide.test.js` asserting the `getAttribute('data-theme')` branch is present in `lib/curriculum-charts.js`. Behavioral verification is harder because jsdom's theme state doesn't drive real chart rendering — source-string is enough.

**Note**: if the chart text color STILL looks off after this fix (e.g., `getTextColor` returns something other than the expected `#E8E8E8` or similar light color for night mode), there may also be missing CSS custom properties (`--chart-text`, `--chart-grid`, `--chart-point`) that the renderer reads. Codex's concern language suggests these variables are referenced in `curriculum-charts.js` but not defined in the study guide's CSS. Grep `lib/curriculum-charts.js` for `getComputedStyle.*--chart` or `--chart-text` — if found, add the corresponding CSS variables to BOTH theme blocks in `study_guide_diagnostic.html` (around line 20-43). For `:root` (paper/light) set `--chart-text: #333333; --chart-grid: rgba(0,0,0,0.1); --chart-point: #36A2EB;`. For `:root[data-theme="night"]` set `--chart-text: #E8E8E8; --chart-grid: rgba(255,255,255,0.1); --chart-point: #6FAEFF;`. Pick realistic values that match the study guide's existing palette.

## Fix 4 (CONCERN 2) — Chart instance memory leak

**Bug**: each time `attachMedia` is called for a chart question, it generates a fresh canvas ID via `sg-chart-${chartCounter++}` (`study_guide_diagnostic.html:3061` or nearby), and `renderChartNow` stores the Chart.js instance in `window.chartInstances[canvasId]`. When the active probe changes, `renderActiveProbe()` does `ui.active.innerHTML = ''` (around line 4260-4261), removing the canvas from the DOM — but NOT deleting the entry from `window.chartInstances`. Over a long session, the registry grows unbounded with detached Chart.js instances holding references to orphaned DOM nodes + event listeners.

**Fix**: before `ui.active.innerHTML = ''` (find the exact line in `renderActiveProbe`), walk the existing children for any `<canvas>` elements that match the `sg-chart-*` id pattern and destroy their chart instances:

```js
// Prune any Chart.js instances attached to canvases in the old active probe before tearing down the DOM
if (window.chartInstances && ui.active) {
  const oldCanvases = ui.active.querySelectorAll('canvas[id^="sg-chart-"]');
  oldCanvases.forEach(c => {
    const inst = window.chartInstances[c.id];
    if (inst && typeof inst.destroy === 'function') {
      try { inst.destroy(); } catch (_) { /* ignore */ }
      delete window.chartInstances[c.id];
    }
  });
}
ui.active.innerHTML = '';
```

Place this block immediately before the `innerHTML = ''` assignment. Wrap in a defensive guard so it no-ops when `chartInstances` is absent.

If jsdom makes this hard, source-string is sufficient.
