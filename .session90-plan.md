### Classification scheme

For each question, compute a `status` field based on the prompt text and attachments shape:

| Status | Meaning | Action needed |
|--------|---------|---------------|
| `OK` | Question is self-contained: prompt is answerable from text alone OR all referenced visuals are in attachments and renderable by the study guide | None |
| `OK_TABLE` | Has table attachment; study guide already renders tables | None |
| `CHART_MISSING_RENDERER` | Has `attachments.chartType` but study guide has no chart renderer | Phase 2 lifts the renderer — will flip to OK |
| `IMAGE_NEEDS_FILE` | Has `attachments.image` pointing at a PNG path that doesn't exist on disk | User must obtain the PNG |
| `IMAGE_OK` | Has `attachments.image` AND the file exists on disk | None (study guide `attachMedia` already renders images) |
| `CONTEXT_ORPHAN` | Prompt text mentions "the graph" / "the chart" / "the table" / "the diagram" / "the histogram" / "the boxplot" / "the scatterplot" / "shown" / "below" / "pictured" BUT attachments has no matching artifact | Flag for user review — data issue in source |
| `CONTEXT_UNCLEAR` | Prompt language is ambiguous (e.g., "the following data") but attachments missing — could be authoring style or real gap | Flag for manual review |
| `NO_VISUAL_NEEDED` | Prompt is pure computation (e.g., "Compute P(X < 3) for X ~ Bin(10, 0.5)") with no visual references | None |

**Regex for orphan detection** (case-insensitive): `/\b(the\s+(graph|chart|table|diagram|histogram|boxplot|box\s*plot|scatterplot|scatter\s*plot|dotplot|dot\s*plot|display|figure|plot|image|picture|bar\s*chart|normal\s*curve|distribution\s+shown|following\s+(data|figure|graph|table|histogram|boxplot|scatter|output|display)))\b/i`. Tune as needed.

### Integration into attachMedia

Extend `attachMedia` at line 3059:

```js
function attachMedia(attachments) {
  const hasTable = Array.isArray(attachments && attachments.table) && attachments.table.length;
  const hasImage = attachments && typeof attachments.image === 'string' && attachments.image.trim();
  const hasChart = attachments && typeof attachments.chartType === 'string' && attachments.chartType.trim();
  if (!hasTable && !hasImage && !hasChart) return null;
  const wrap = make('div', 'probe-attachments');

  // existing table branch unchanged
  // existing image branch unchanged

  if (hasChart) {
    // Use the 2-phase pattern from curriculum_render charts.js
    const canvasId = `sg-chart-${chartCounter++}`;
    wrap.insertAdjacentHTML('beforeend', window.getChartHtml(attachments, canvasId));
    // Defer the render until the canvas is in the DOM
    requestAnimationFrame(() => {
      if (window.renderChartNow) window.renderChartNow(attachments, canvasId);
    });
  }

  return wrap;
}
```

Key points:
- `chartCounter` is a module-scoped counter so each chart canvas gets a unique ID.
- `requestAnimationFrame` defers `renderChartNow` until after the caller appends `wrap` to the DOM — the canvas must exist before Chart.js can bind to it.
- Graceful degradation: if `window.getChartHtml` or `window.renderChartNow` is missing (e.g., chart.min.js failed to load), the question still renders the prompt + any other attachments; the chart area just stays empty. Wrap the `hasChart` branch in `if (window.getChartHtml && window.renderChartNow)`.

### Cleanup of chart instances

`renderChartNow` destroys any existing chart at the same canvasId via `window.chartInstances[canvasId].destroy()`. If the study guide re-renders the active probe while a chart is still mounted (e.g., theme toggle, layout refresh), the destroy-then-recreate pattern should keep things clean. But verify: when the active probe changes, is the old probe's chart canvas removed from the DOM? If yes, no action needed. If no, explicitly call `destroy()` on any orphaned chart instances before creating new ones.

## Known gotchas

- **Chart.js in jsdom**: jsdom has no canvas support (session 89 probe log showed `HTMLCanvasElement.prototype.getContext` is not implemented without the `canvas` npm package). Any behavioral test that calls `renderChartNow` will fail in jsdom. Two options: (a) stub Chart.js with a mock that returns a fake instance, (b) skip the chart-render behavioral test and rely on source-string assertions + manual browser verification. Pick (b) for simplicity.
- **`window.getChartHtml` namespace**: curriculum_render's charts.js uses `window.charts = window.charts || {}` to avoid collisions. Verify the lifted copy doesn't collide with anything in the study guide. Grep `study_guide_diagnostic.html` for `window.charts` and `getChartHtml` before lifting.
- **`generateChartColors`**: charts.js references a `generateChartColors(count)` function that returns a palette. This may live in `charthelper.js` or be defined inline in charts.js. Verify it's lifted too.
- **Dispatch verification** (s88b lesson): CC will run `git status` and vitest independently. Don't fabricate.
- **curriculum.js as source**: the file is 37,913 lines. Parsing the full `EMBEDDED_CURRICULUM` array literal may be slow. Consider using a streaming regex extract or Node `vm` module. Benchmark if the audit takes more than 30 seconds.
- **File encoding**: curriculum.js may have CRLF on Windows. Node should handle it, but verify the regex-based extraction doesn't break on line endings.
