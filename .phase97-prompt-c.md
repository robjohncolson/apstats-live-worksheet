# Phase 97C — Font-lookup VRAM Decoder Utility

## Context
TI-84 CE ROM transpiler. We've captured many VRAM screens but verify them via ASCII art. A font decoder would match rendered pixel blocks to ASCII characters programmatically, enabling text-level verification of existing and future renders.

From Phase 80+ notes: font data exists at `0x003d6e` with **28 bytes/glyph**. Glyph dimensions need verification — likely 11 rows × 8 cols (11×8=88 bits = 11 bytes, not 28), or 14 rows × 16 pixel cols (14×2 bytes = 28 bytes ✓), or another layout. **Inspect the actual bytes and confirm.**

### Step 4: Build VRAM-to-text decoder
```js
export function matchVramText(mem, row0, row1, col0, col1, fontBase, romBytes) {
  // Iterates VRAM region in glyph-sized steps, matches each cell against font table.
  // Returns an array of strings (one per row of glyphs).
  //
  // For each candidate cell at (vramRow, vramCol):
  //   1. Read the W×H pixel block from VRAM (non-white/non-sentinel = "on").
  //   2. Compute Hamming distance vs each glyph in font table.
  //   3. Pick best match; return its ASCII char.
  //   4. If distance is too high (>30% mismatch), return '?' or ' '.
}
```

VRAM access: `mem[0xD40000 + (row*320 + col)*2]` and `+1` byte → 16-bit BGR565 pixel. `0xAAAA` = sentinel (undrawn), `0xFFFF` = white, anything else = fg.
