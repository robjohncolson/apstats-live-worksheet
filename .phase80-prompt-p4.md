Phase 80-4: Fix browser-shell showScreen memory allocation (TI-84 CE ROM transpilation)

## Context
Session 14 discovered that `browser-shell.html` showScreen paths fail in the browser — every render button (MODE, CATALOG, error banners, P62/P64/P68/P69/P77/P78) terminates at step 104 with `missing_block at 0xffffff`. This has been broken since Phase 40b (commit 2329783, 2026-04-12 13:34) but was never visually verified.

**Hypothesis**: The CC-side Node probes (e.g., `probe-phase78-parents.mjs`) work because they explicitly allocate a 16MB memory buffer:
```js
const mem = new Uint8Array(0x1000000);
mem.set(romBytes);
const executor = createExecutor(blocks, mem, { peripherals });
```

The browser's `showScreen` uses `romBytes` directly from `decodeEmbeddedRom()`, which may return only ~4MB (ROM size, not full 24-bit address space). If the executor writes to RAM addresses (0xD00000+, 0xE00000+, 0xFF0000+), those writes go out of bounds and wrap around or fail, corrupting execution state.

**Fix**: Modify `showScreen` in `browser-shell.html` to allocate a 16MB `Uint8Array`, copy romBytes into it, and pass that as the mem parameter to createExecutor. Apply the same fix to `renderErrorBanner` (which also creates a fresh executor per click).

### 1. Modify `browser-shell.html`
Find the `showScreen` function (starts around line 720). The current code has:
```js
const romBytes = decodeEmbeddedRom();
const p2 = createPeripheralBus({ pllDelay: 2, timerInterrupt: false });
const ex2 = createExecutor(PRELIFTED_BLOCKS, romBytes, { peripherals: p2 });
```

Replace with:
```js

```
