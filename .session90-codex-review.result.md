## Phase 2 — Chart rendering lift
- **Blocker** — `lib/curriculum-charts.js:23-35` still detects dark mode with `document.body.classList.contains('dark-theme')`, but the study guide never sets that class. Its theme system is `:root[data-theme="night"]` in `study_guide_diagnostic.html:20-43`, toggled via `document.documentElement.setAttribute('data-theme', safe)` in `study_guide_diagnostic.html:5001-5004`. Because the page also defines no `--chart-text` / `--chart-grid` / `--chart-point` variables, `getTextColor()` falls back to `#333333` and that value is reused for chart labels throughout the renderer (for example `lib/curriculum-charts.js:185,196,299`). In night mode the chart text is effectively dark-on-dark. Suggested fix: make `isDarkMode()` read the study guide’s actual theme source (`document.documentElement.getAttribute('data-theme') === 'night'`) or define real `--chart-*` variables for both themes.
- **Concern** — `study_guide_diagnostic.html:3061` generates a fresh `sg-chart-${chartCounter++}` ID every render, `lib/curriculum-charts.js:82-98` only destroys an instance when that same canvas ID is reused, and `renderActiveProbe()` throws away the old card with `ui.active.innerHTML = ''` at `study_guide_diagnostic.html:4260-4261` without pruning `window.chartInstances`. Walking through many chart questions will leave detached Chart.js instances behind in the registry. Suggested fix: destroy tracked instances before replacing `ui.active`, or track the current card’s chart IDs and delete them from `window.chartInstances` when the active probe changes.
- No bugs found in script load order or the dependency lift itself. `study_guide_diagnostic.html:389-391` loads Chart.js, then the datalabels plugin, then `curriculum-charts.js` before the main app code, and `lib/curriculum-charts.js:6` confirms `generateChartColors()` was carried over.
