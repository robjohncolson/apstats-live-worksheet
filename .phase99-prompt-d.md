# Phase 99D — End-to-end home screen verification probe

## Context

We now have a home screen composite render that works (Phase 91/93/96), and **Phase 99A is rewriting the font decoder to 1bpp 16-wide format in parallel**. Once Phase 99A lands, we need a golden regression test that runs the full composite, decodes the mode text row, and asserts it matches the expected "Normal Float Radian" seed. Every subsequent home-screen change should have to pass this probe.

## Inputs

**Home screen 5-stage composite** (from `TI-84_Plus_CE/browser-shell.html` `showHomeScreen` handler):

1. `executor.runFrom(0x0a2b72, 'adl', { maxSteps: 30000, maxLoopIterations: 10000 })` — status bar background (r0-34)
2. Seed `mem[0xD020A6 + i] = "Normal Float Radian       ".charCodeAt(i)` for i in 0..25 (26 bytes, ASCII)
3. `executor.runFrom(0x0a29ec, 'adl', { maxSteps: 30000, maxLoopIterations: 10000 })` — home row strip (r17-34)
4. `executor.runFrom(0x0a2854, 'adl', { maxSteps: 50000, maxLoopIterations: 10000 })` — history area (r37-74); note: bumped to 50000 in Phase 98D
5. Direct fill r220-239 with 0xFFFF (entry line background)

Prior to stage 1, a cold boot must run: `executor.runFrom(0x000000, 'z80', { maxSteps: 20000, maxLoopIterations: 32 })`, then `cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0; cpu.sp = 0xD1A87E - 3; mem.fill(0xFF, cpu.sp, 3)` (existing harness pattern — see `probe-phase98c-followup.mjs` for reference).

After stage 5 the VRAM should contain drawn=25686, fg=11516, rMin=0, rMax=239. The mode text appears in **rows 17-34** with characters at some column stride (measure it — it's probably 8 or 13).

**Font decoder API** (from `TI-84_Plus_CE/font-decoder.mjs`, post-Phase 99A):

```js
import { buildFontSignatures, decodeTextStrip, FONT_BASE, GLYPH_WIDTH, GLYPH_HEIGHT } from './font-decoder.mjs';

const sigs = buildFontSignatures(romBytes);
const text = decodeTextStrip(mem, startRow, startCol, numCells, sigs, maxDist, mode);
// mode: 'normal' | 'inverse' | 'auto' (default 'auto' — picks best of both per cell)
```

## Task

Write a new probe `TI-84_Plus_CE/probe-phase99d-home-verify.mjs`. It should:

1. Import `createExecutor` from `./cpu-runtime.js`, `createPeripheralBus` from `./peripherals.js`, and `buildFontSignatures`/`decodeTextStrip` from `./font-decoder.mjs`. Load `./ROM.transpiled.js` via dynamic import (see `probe-phase98c-followup.mjs` for the pattern).
2. Allocate a 16MB `Uint8Array`, copy ROM into it, clear VRAM (`0xAA` bytes in 0xD40000..0xD52C00).
3. Cold boot the harness exactly as in `probe-phase98c-followup.mjs` (20000 steps at z80, then set `halted=false`, zero iff1/iff2, reset SP as shown above).
4. Run stage 1 (0x0a2b72).
5. Seed the mode buffer with the ASCII string `"Normal Float Radian       "` (26 chars, space-padded).
6. Run stage 3 (0x0a29ec).
7. Run stage 4 (0x0a2854) with `maxSteps: 50000`.
8. Fill rows 220-239 with `0xFFFF` (2 bytes per pixel × 320 cols × 20 rows).
9. Build font signatures from `romBytes`.
10. **Find the correct startRow and startCol for the mode text strip.** Strategy: scan rows 17-34 for the first non-sentinel pixel column, use that col - 0 as startCol (or just start at col 0). For startRow, probe rows 17..34 and pick the one with the most non-sentinel pixels — that's the text baseline row. Or, since Phase 98A showed cells are rendered at consistent vertical positions inside the 18-row strip, try startRow = 20 (center of a 14-tall glyph within the 18-row strip) as a sensible default and adjust if the decode looks wrong.
11. Call `decodeTextStrip(mem, startRow, startCol, 26, sigs, 40, 'auto')` to decode 26 cells starting at that position. (Use maxDist=40 for the wider 16-col glyphs.)
12. Print: `drawn=<n> fg=<n> bg=<n> rMin=<n> rMax=<n>`, the raw decoded string, and three assertions:
    - `text.includes('Normal')` — PASS or FAIL
    - `text.includes('Float')` — PASS or FAIL
    - `text.includes('Radian')` — PASS or FAIL
13. Exit code 0 if all three pass, 1 otherwise.

**Also try multiple startRow values** (18, 19, 20, 21, 22) and multiple startCol values (0, 8, 16) and report the best-matching combination in case the default is wrong. Log all attempts so the user can see what was tried.

## Deliverables

1. New `TI-84_Plus_CE/probe-phase99d-home-verify.mjs`
2. Run it: `node probe-phase99d-home-verify.mjs 2>&1 | tee phase99d-verify.log` and commit the log
3. New `TI-84_Plus_CE/phase99d-report.md` with: (a) best-match (row, col) for the mode strip, (b) decoded text, (c) pass/fail of the 3 assertions, (d) any glyph-alignment issues noted.

## Important

- If Phase 99A's font decoder rewrite is incomplete when this runs, the decode will return '?' for most cells. That's fine — report it as "blocked on 99A" in the report and exit 1. Do NOT try to rewrite the decoder yourself.
- Use `probe-phase98c-followup.mjs` as the harness template. Do not invent a new harness pattern.
- The composite should produce drawn≈25686; if you see drawn=0 or drawn≥40000, the harness is broken — stop and log the failure.
- Do NOT touch `browser-shell.html`, `font-decoder.mjs`, `peripherals.js`, or `ROM.transpiled.js`. This task is probe-only.
