### 1. `phase77c-028f02-trace-report.md`
Markdown report with:

#### Section A: Static disassembly of 0x028f02
- Dump first 80 bytes starting at 0x028f02 in ROM.rom
- Use `ez80-decoder.js` (import it as a module — it exports a decoder function) to produce instruction-level dasm in ADL mode, 60 instructions deep
- Show opcodes + mnemonics + register usage
- Interpret: how is A used? How is HL used? Is there an offset lookup (e.g., `ld bc, (table_base + a*3)`)? Does it call 0x0059c6 or 0x0a1cac? Does it ret or jp?

#### Section B: Caller scan
- Scan ROM.rom bytes for the 24-bit ADL CALL pattern `CD 02 8F 02` (0xCD opcode + little-endian 3-byte address 0x028f02)
- Scan for `rst 0x08 ; dw <slot_offset>` where the slot at 0x020104+offset resolves to 0x028f02
- List each caller: address in ROM, containing function entry (use PRELIFTED_BLOCKS to find the function that owns that address)
- For each caller block, use `ez80-decoder.js` to dump the 10 instructions BEFORE the call to 0x028f02 (to see what A/HL setup looks like)

#### Section C: Sibling hypothesis
- From 0x028f02's disassembly, identify its distinguishing byte signature (first 6-10 bytes)
- Scan ROM.rom for similar byte patterns that could be a sibling function doing the same operation with a different table
- For each sibling candidate, dasm the first 15 instructions
