## Fix 1 (BLOCKER A) — Rebind auth form listeners after sign-out

**Bug**: `refreshAuthPanelVisibility` uses `section.innerHTML = ''` to tear down the signed-in strip and rebuild the auth form. That destroys the original DOM nodes AND all their listeners. The original init-time wiring at `study_guide_diagnostic.html:5015-5041` attached handlers to `ui.password` (Enter key), `ui.username` (change event), `ui.loginBtn` (click), and `#studentCreateLink` (click). Only the login button + create link are re-wired in the restore branch; password Enter and username change stop working after the first sign-out.

**Fix**:
1. Extract the auth form listener wiring into a helper function, e.g. `wireAuthFormListeners()`. This function:
   - Re-queries `ui.username`, `ui.password`, `ui.loginBtn`, `ui.createLink` (the create link needs to be cached too — add it to the `ui` object at line ~1897 if it isn't already).
   - Attaches the password Enter-to-login keydown handler.
   - Attaches the username change handler that calls `clearAuthSession()` + `refreshAuthPanelVisibility()` if the new selection differs from `authSession.username`.
   - Attaches the login button click handler.
   - Attaches the create link click handler (`showCreateUserModal`).
2. Call `wireAuthFormListeners()` from `init()` (replacing the current inline wiring at ~5015-5041) AND from the restore branch inside `refreshAuthPanelVisibility` after the form HTML is recreated.
3. **Important**: the `ui` object caches DOM references. After rebuilding `.student-info`, those cached refs are stale. Either (a) re-query inside `wireAuthFormListeners()` and update `ui` fields, or (b) don't cache in `ui` at all — query fresh each time. Pick (a) for minimal diff.

**Tests**: add a test asserting `wireAuthFormListeners` (or equivalent) is defined and called from both init and the restore branch. Source-string style is fine.

## Fix 2 (BLOCKER D) — Gate disclosures on non-paper grades

**Bug**: paper mode (`Mark complete (paper)`) sets `data.frqGrade = { score:'paper', ... }` without any answer verification. `renderGrade` then shows the rubric + worked solution because `grade.score` is truthy. A student can click paper mode → immediately see the solution → write it on paper → "hand in." Free answer key.

**Fix**: in `renderGrade`, change the visibility gate from `if (grade && grade.score)` to `if (grade && grade.score && grade.score !== 'paper')` for BOTH the `.sg-grade-rubric` AND `.sg-grade-solution` disclosure blocks. Leave the rest of `renderGrade` alone — the raw/effective score block can still show "paper" as before.

Rationale: paper mode is for students writing answers on paper and handing them to the teacher for manual grading. They shouldn't get the answer key unconditionally. If they want rubric/solution feedback, they can switch to AI grading and submit real content.

**Tests**: add a test asserting `renderGrade` with `grade = { score: 'paper' }` does NOT append either disclosure. Also assert the normal path (`{ score: 'E' }`) DOES append them. Use source-string assertion to check the condition appears, plus a behavioral test if feasible.

## Fix 3 (CONCERN A) — Call `refreshSyncStatus()` on auth state changes

Or — cleaner — call it from inside `refreshAuthPanelVisibility()` at the start, since that's already triggered on every auth state change. Pick whichever is smaller-diff.

**Tests**: source-string assertion that `refreshSyncStatus` is called inside `refreshAuthPanelVisibility` OR immediately after `clearAuthSession` in the sign-out handler.
